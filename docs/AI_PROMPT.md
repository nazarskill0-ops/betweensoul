`Промпт для ИИ`

Вставляется ИИ (Cursor / Claude / Copilot) целиком, вместе с текстом задачи.
Ниже черты — сам промпт.

---

Ты пишешь код для Calmi — маркетплейса украинских психологов. Ориентир по
продукту — rozmova.me: клиент ищет психолога по теме запроса (тревога, ПТСР,
выгорание), методу терапии, цене и языку, бронирует время и платит онлайн.

Стек: Next.js App Router + TypeScript + Tailwind v4 + Supabase + TanStack
Query + Zustand + Zod + react-hook-form. Архитектура уже выбрана и не
обсуждается. Твоя работа — выполнить одну поставленную задачу, не выходя за её
рамки.

## Как устроен код

- Одна фича = одна папка `src/features/<имя>/`. Внутри: `schema.ts` (Zod-схемы
  и типы), `api.ts` (единственное место, где берутся данные), `hooks/` (обёртки
  TanStack Query), `components/`. Эталон — `src/features/psychologists/`,
  повторяй его форму.
- `src/components/ui/` — переиспользуемые мелкие компоненты (кнопка, инпут).
  `src/components/layout/` — хедер/футер. `src/lib/` — утилиты без привязки к
  фиче.
- Файлы в `src/app/` — тонкие: страница только собирает компоненты из
  `features/` и `components/`. Никакой логики и запросов в page.tsx.
- Готовые таксономии лежат в `src/features/psychologists/schema.ts`:
  `TOPICS` (темы запросов), `SPECIALIZATIONS` (методы терапии),
  `CLIENT_CATEGORIES`, `LANGUAGES`. Не выдумывай свои списки.
- Эталон формы: `src/features/marketing/components/PartnerForm.tsx`.

## Правила данных

1. Серверные данные — только через хуки TanStack Query из `features/<имя>/hooks/`.
   Запрещено: `fetch`/`supabase` прямо в компоненте, серверные данные в Zustand
   или в копии через `useState`.
2. Компонент, который зовёт хук с данными, ставь как можно НИЖЕ по дереву — у
   того элемента, который эти данные рендерит (сетку карточек рендерит
   `CatalogGrid` — значит `usePsychologists` зовёт он, а не страница). Страница
   не собирает данные за всех детей.
3. Zustand — только состояние интерфейса (модалка, шаг визарда). Никогда не
   сервер-данные.
4. Фильтры, поиск, пагинация живут в URL (`useSearchParams`), не в стейте.
5. Бэка для задачи может не быть. Тогда фейковые данные кладёшь в
   `src/features/<имя>/mock.ts`, возвращаешь их из `api.ts` с пометкой
   `// TODO(backend)` и искусственной задержкой ~300мс. Компоненты не знают,
   что данные фейковые.
6. Деньги — целые копейки (250 грн = 25000), никаких float. Константы из
   `src/lib/config.ts`, не хардкодь.
7. Время в данных — UTC. В киевское переводишь только при отображении.
8. Любой пользовательский ввод валидируется Zod-схемой из `schema.ts`; формы —
   react-hook-form + zodResolver.

## Правила оформления

9. Стили — только Tailwind с токенами проекта: `bg-sage`, `bg-sand`,
   `bg-sage-light`, `text-ink`, `text-ink-muted`, `text-rose`,
   `border-sand-dark`, `rounded-card`, `font-display` (заголовки). Никаких
   своих hex-цветов, css-файлов, styled-components. Референс внешнего вида —
   `src/app/page.tsx` и `_design_ref/index.html`.
10. Все тексты интерфейса — на украинском.
11. Мобильная версия обязательна (проверяй на 375px).

## Границы

12. Делай только свою задачу. Не рефактори чужое, не переименовывай, не
    «улучшай попутно». Заметил проблему рядом — скажи, но не чини.
13. Не трогай: `src/lib/payments/`, `src/lib/supabase/`, `src/lib/config.ts`,
    `supabase/migrations/`, `src/app/layout.tsx`, `src/app/providers.tsx`,
    `package.json` (новые зависимости не ставить), `.env*`, конфиги в корне.
14. Секреты не попадают в клиентский код; в браузере доступны только
    `NEXT_PUBLIC_*` переменные.
15. Если задача противоречит этим правилам или что-то непонятно — остановись и
    сформулируй вопрос, не изобретай обход.
